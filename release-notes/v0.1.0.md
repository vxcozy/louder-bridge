# Louder Bridge 0.1.0

This is a prerelease for testing Louder Bridge with the Work Louder Codex
Micro. It is not the stable v1 release.

Louder Bridge connects the Micro to local Claude Code sessions in Claude
Desktop. The six Agent Keys show session state and open the matching session.
Holding MIC starts voice input; releasing it stops. The key beside MIC sends
Return for submission and approval prompts.

For toggle-style composer buttons, Louder Bridge now clicks once on MIC press
and again on release. Press-and-hold buttons still use a continuous hold. The
Cowork composer route still needs physical release testing.

## Tested hardware

The development build passed a focused Bluetooth test on August 2, 2026:

- macOS 26.5.2
- Claude Desktop 1.24012.9
- Codex Micro firmware v0.4.1
- MIC hold and release in Claude Code
- dictated text inserted into the active composer
- one Return event from the send key
- running and complete lifecycle lighting

Codex was closed during the passing test. When both apps were open, the same
MIC input also reached Codex. Closing Codex removed that conflict.

On August 3, an installed development build passed a second Bluetooth run.
The bridge left the Micro with Codex while Codex was open. After Codex quit and
Claude Code opened, the bridge connected without an app or agent restart. MIC
hold and release inserted dictated text in Claude, and the adjacent key
submitted it once. Post-test status showed Codex open, Claude closed, and the
Micro released by the bridge.

The tester also confirmed MIC hold and release, dictated text, and the adjacent
send key in Claude Code over USB-C. The wired restart, approval, and
power-cycle matrix has not been run yet.

The release candidate now checks whether Codex is open before opening the
Micro. When both apps are already open, it leaves the Micro to Codex and shows
one notice.
If Codex opens later, the bridge releases the device before showing the notice.
It reconnects after Codex quits. If releasing the Micro fails, the bridge
retries the same cleanup before opening another driver, even if Codex closes in
the meantime. Failures to launch the notice are recorded in the private error
log. Automated tests cover the retry path, but the conflict notice and release
path still need a physical test with both apps kept open.

If either desktop process check fails, diagnostics mark that app as unknown and
the service releases the Micro instead of guessing. It reconnects after the
checks recover.

Double-tap voice latching, the visible Cowork composer route, approval prompts,
wired restart and power-cycle cases, and clean-machine installation still need
physical qualification. This is not a completed v1 acceptance run.

## Privacy

The bridge runs locally. It does not collect telemetry, audio, transcripts, or
prompt content. Claude owns voice input when its composer microphone is
available. Claude Code views without that control use macOS Dictation.
Hook requests contain only the session ID, event name, and notification type.
Health diagnostics do not return session IDs or working directories.
They keep the timestamp, type, and action from the last device event after the
bridge releases the Micro.
Invalid hook requests return a fixed error without quoting the request body.
If a diagnostic adapter fails, the health endpoint returns a fixed error and
keeps the local server running.
Logs redact UUID-shaped identifiers and authentication tokens, including from
older files found during setup.
Log reads and writes reject symbolic links and multiply linked files, including
links introduced after the background agent starts.
The local authentication token is created atomically and validated without
following symbolic links.

## Release files

The release includes a ZIP archive, its SHA-256 checksum, and an SPDX SBOM. The
SBOM records the SHA-256 of the embedded Node.js runtime, and release
verification compares that value with the binary extracted from the ZIP.
The SBOM also records the Git revision. Development builds mark dirty source,
while Developer ID builds require a clean checkout.
Release jobs for the same tag run one at a time. If a job fails after creating
the draft, a rerun updates that draft, replaces the three expected files, and
checks their remote byte sizes. It will not change a published release or a
draft containing another asset.

For notarized builds, verification also requires the app, launcher, and Node.js
runtime to share one Developer ID team and secure signing timestamps.
Notarization creates the stapled ZIP and checksum beside the current pair. It
then moves both current files into verified backups before publishing either
replacement. If creation or publication fails, it restores the old pair when
those backups are intact. File-identity checks keep rollback from overwriting a
file changed by another process or deleting a published file after its backup
disappears.
Archive checks reject unsafe paths, links, special files, group- or
world-writable entries, and binaries that are not arm64-only. Verification
also rejects archives with more than 512 entries, 256 MiB compressed, or 512
MiB uncompressed before extraction.
The native launcher uses strong stack protection and fortified library calls.
Package verification checks the compiled binary for those protections.
Internal native test commands are left out of production launchers. Package
verification calls each reserved test option and requires the launcher to
reject it.
The build also runs the packaged location preflight through the signed
launcher before it creates the ZIP.
The project and protocol licenses must match the reviewed source, and the
bundled Node.js license must be present and complete.

Setup and removal update only Louder Bridge hooks in Claude's settings. If an
operation fails, rollback keeps unrelated changes made while that operation
was running. Upgrades and removal also recognize installation paths that
contain an apostrophe.

Permission onboarding waits up to five minutes for each macOS approval. Setup
continues as soon as you grant access. If the wait expires, a dialog identifies
the missing permission and opens its System Settings pane. The app then exits,
and source setup rolls back before returning an error.
Source setup no longer creates an `open -W` helper. It waits briefly for the
onboarding process to appear, then follows the app directly. If macOS closes
the app after a permission change, setup can reopen it up to five times. Each
app wait has an eleven-minute deadline.

`npm run setup` runs the transaction in a detached worker. If npm or the
terminal exits, the worker restores the previous app and configuration before
it stops. A process-level test kills the parent without warning and confirms
that rollback finishes.

Source builds derive the launcher's Mach-O UUID from its compiled contents, so
rebuilding unchanged native code keeps the same local launcher identity.
Release builds keep the linker's UUID for symbolication.

Before source setup, `npm run doctor` checks that the Mac has the compiler and
SDK needed to build the native driver. The installed app checks its bundled
driver instead.

During logout, upgrades, and service restarts, Louder Bridge closes its local
server and releases voice input even if the Micro reports a cleanup error.
Startup also releases the Micro if the hook server cannot bind its local port.
Agent Key navigation stops waiting after five seconds if macOS never reports
whether the Claude URL opened. A later process error does not crash the
service.
Repeated press reports from the same Agent Key are ignored until its release
arrives. Reconnecting clears held-key state, so the first press on the new
connection still works.
If the native dictation helper stops responding, the bridge waits for it to
exit and escalates termination before accepting another MIC gesture.
Voice startup reads at most 4 KiB from the helper and stops reading once it is
ready. This bounds memory use if the helper sends bad startup data during a
recording.
The device service also recovers when its native driver fails before emitting
an exit event. A late exit from that failed process cannot tear down a
replacement connection.

Source setup waits for permission onboarding and an authenticated health
response from the installed version before deleting the previous app backup.
Failed activation restores the previous launch agent and installation. SIGINT
and SIGTERM also cancel onboarding and finish rollback before source setup
exits. Launch-agent removal checks the plist again after stopping the service.
Rollback leaves a file alone if another process changed or created it during
activation.
The authenticated activation check waits up to fifteen seconds. This gives
launchd time to clear its ten-second restart throttle after a short-lived agent
run.

If launchd reports an error while stopping the previous agent, rollback retries
the stop and reloads the unchanged agent after a successful retry. The original
launchd error is still reported.

First launch checks the app's resolved location before asking for permissions
or changing Claude settings. Louder Bridge must be inside the system or
per-user Applications directory. This stops a copy opened from Downloads or a
temporary App Translocation mount from saving a login-agent path that can
disappear.

When the hook server is down, the status command reads the installed app
version and launches a fresh app probe for Input Monitoring and Accessibility.
Onboarding uses the same probe so a newly granted permission takes effect
without reopening Louder Bridge by hand.

The release workflow accepts tags only when their commit belongs to the
protected default branch. Before building, it rejects missing or malformed
signing and notarization credentials without printing their values. It also
audits production dependencies before signing or packaging the app. The draft
release step uploads the exact archive, checksum, and SBOM for the tag version.
Signing adds the temporary keychain to the runner's existing search list and
passes that keychain directly to `codesign`. Cleanup restores the original
search list before deleting the temporary keychain.
Checkout does not save the GitHub token in git configuration. Only the draft
release step receives the write-capable token. Source checks run before any
repository script receives signing or notarization credentials.
The repository security check rejects certificate, private-key, keychain, and
provisioning files by filename, including binary credential files.
The authorship check scans commit messages, current files, and every file
version in reachable Git history. Removing a credited file in a later commit
does not make the check pass.

## Why this is still a prerelease

The device protocol, Claude session navigation, and Claude voice route are
experimental interfaces. A stable v1 release requires supported interfaces
from Work Louder and Anthropic.
